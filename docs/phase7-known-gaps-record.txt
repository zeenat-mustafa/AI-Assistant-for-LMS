  embedding_error NULL). The stored Chroma DOCUMENT is the full raw
  `![...](data:image/png;base64,...)` string, and the VECTOR represents only

  the 0.35 similarity threshold for a real question; if one ever did, 7.5
  would put the raw base64 document into the chat prompt and its citation
  snippet.

  THIS WAS A CROSS-FEATURE EXPOSURE; WHEN 7.6 WAS COMMITTED, ONLY 7.6's SIDE
  OF IT WAS CLOSED. (Paragraph kept as written at 7.6 commit time.)
  7.6's topic-mode fix stops quiz generation from ever surfacing these four
  entries, but 7.5's student-chat retrieval (POST /student-chat/stream)
  reads Chroma's stored document field directly with no equivalent
  protection — if a student's chat question retrieved one of these entries
  today, the raw base64 would still reach the chat prompt. Do not read this
  entry as fixed: the recommended backfill below is what resolves both
  consumers (quiz and chat) at once, and it has not been run.

  Root cause fixed going forward (7.6): extract_notebook_structure() and
  extract_notebook_structure_from_bytes() gained an opt-in
  strip_images=True, which replaces embedded base64 images with
  "[image omitted]". It is on for the upload embedding flow
  (routers/assignments.py) and scripts/backfill_embeddings.py, so no future
  upload or backfill embeds image payloads. It is deliberately OFF (default)
  for grading and rubric generation (evaluator.py, rubric.py), whose prompts
  stay byte-identical; six real student submission notebooks in session 4
  contain these same images, and changing grading input would need its own
  re-verification pass. The quiz (7.6) is not affected by the stale entries:
  it reads notebook text from the source files with strip_images=True, and
  topic mode uses the re-read cell text, never Chroma's stored document.

  THRESHOLD FINDING — THE LEAK WAS LIVE, NOT JUST DEFENSE IN DEPTH. The

  group_by_cities.png) sits inside the first 256 tokens, so ordinary

  re-reads stripped source cells); 7.5's chat was genuinely exposed.

  After the backfill, the same queries score the four entries at 0.1491 and

- A MULTI-SESSION QUIZ CAN MIX TOPICALLY UNRELATED MATERIAL INTO ONE
  NONSENSICAL QUESTION. Real example from 7.6's re-verification: a
  multiple_sessions quiz over sessions [4, 8] (pandas notebooks + the
  AI-agents lecture) produced, as Q2: "In the Split-Apply-Combine procedure
  demonstrated with Pandas GroupBy objects, what primary role does
  short-term memory or tracking play when compared against the agent
  execution loop discussed in later sessions?" Its source_citation was
  correct (week 10_day1.pptx, slide 10) and its marked answer is correct for
  that slide, but the question itself blends two unrelated topics and makes
  no sense.

  This is a real, disclosed quality limitation of combining material from
  topically unrelated sessions in one quiz — not a leak (nothing from a
  completion gap is revealed), and not something to be fixed by altering
  the already-signed-off quiz-generation prompt. The other 4 questions in
  that quiz, and every single-topic quiz verified in 7.6, did not show it.

- REPEAT QUIZZES ON A SMALL NOTEBOOK ARE VERY SIMILAR. Material sampling
  only varies a quiz when a scope's material exceeds the 40k-character
  budget. After the heuristic_hint and hint-cell filters, Week 10_Lab3.ipynb
  has about 2,200 characters of usable text, all of which is sent every
  time, so repeat quizzes on it ask near-identical questions. Accepted
  trade-off of excluding hint cells (7.6 review).

- THE HINT-CELL FILTER EXCLUDES ANY CELL CONTAINING THE WORD "hint"/"hints".
  One whole-word, case-insensitive rule (quiz_generator.is_hint_cell), chosen
  over heading/label patterns because every real hint note found contains the
  word and the one real 💡-non-hint ("💡 Inspiration:") does not. It will
  also drop a cell using the word in ordinary prose ("a hint of
  seasonality"); no real course notebook does this today. Quiz-only — it
  does not change what embedding, chat, or grading see.

- QUIZ CITATIONS SHOW NOTEBOOK CELLS 1-INDEXED ("cell 7"); 7.5's student-chat
  citations return the raw 0-based cell_index. Known, accepted cosmetic
  inconsistency; 7.5 deliberately not changed.
